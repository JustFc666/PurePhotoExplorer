## 二、阶段回顾

### 2.1 S0 地基（10-02 ~ 10-03）

原计划 M0 就要面对 LibRaw + MSVC，风险太靠前。重排后先做**纯 Rust 的 S1 最小闭环**：
格式探测 → 解码 → 缓存 → IPC → 渲染。这个判断后来被反复验证——`ImageDecoder` /
`DecodeTarget` / `RawPipeline` 三个接口从 S1 定型到现在，接 HEIC、PSD、GIF、WebP、RAW、
TIFF、AVIF **一行架构都没改**，只是往 `BitmapBackend` 里加解码器。

### 2.2 S1 单图浏览（10-03 ~ 10-13）

交付 7 项核心 + 6 项规划外能力（打印、文件关联、右键菜单、全屏、预加载、EXIF）。

关键决定：
- **自绘无边框窗口**：标题栏与工具栏合并成一行，代价是原生控件全部不能用（见坑 C7）
- **裁剪交互连改 6 轮**，最后定成「画面始终有框 + 拖角改大小 + 拖内平移，全程画面不动」
- **HEIC / RAW 走纯 Rust**，把 MSVC 从关键路径彻底摘掉

### 2.3 S2 图库（10-14 ~ 10-19）

链路：`pv-index`(SQLite+FTS5) → `pv-scan` → `pv-cache`(L1内存/L2磁盘) → `pv-store` → `pv-lib`。

关键决定：
- **卷身份用 `volume_guid + rel_path`，不存盘符**（U 盘换字母不失效）
- **浏览 ≠ 入库**：左键点目录 = 临时预览（不写索引不写缓存），右键「加入图库」才入库
- **默认排序 = 拍摄时间**，用 `COALESCE(taken_at, added_ts)` 兜底

### 2.4 AI 打标（10-20 ~ 10-23）

CN-CLIP ViT-B/16 零样本打标，ONNX Runtime 推理。词表从 520 条一路收敛到 **111 条**
（规则：以模型判别力为准，不以凑整为目标）。阈值经 24 张人工核对（168 个判断）标定，
最终 **二级 0.42 / 一级 0.40**，美食类单独降到 0.39。

也试过换 ViT-H/14 和「分层打分」，两次 A/B 都是**收益不足，不换**。

### 2.5 人脸归纳（10-23 ~ 10-24）

CLIP 判「人像」假阳性太多 → 彻底把「有没有脸」交给 **YuNet**，CLIP 只负责内容标签。

链路：YuNet 检测（2048 长边）→ SFace `alignCrop` 对齐 → 128 维向量 → 两阶段聚类 →
≥3 张脸才建「人物」。schema v4 新增 `faces` / `persons` 两表。

### 2.6 工程迁移（10-26）

`C:\Users\Fc\WorkBuddy\...` → `J:\WorkBuddy\2026-10-02-22-48-04`。
去掉 3 处写死 C: 的绝对路径，改成按 `__file__` 推导。同步修改了 WorkBuddy 自身的
工作区配置（数据库、显示名、会话 cwd、技能安装表）。

## 三、踩坑清单

按**代价**排序。带 🚧 的是「改代码前必须知道，否则一定重踩」。

### A 类 · 架构与协议

| # | 现象 | 根因 | 修法 / 现状 |
| --- | --- | --- | --- |
| A1 🚧 | 打开图就**栈溢出**，连崩 4 轮 | Tauri 命令返回**大字节数组**时被序列化成 JSON 数字数组，逐元素递归处理 | 改用 `tauri::ipc::Response` 传**裸字节**。⛔ 别回退 base64。护栏 `tests/anim_protocol.rs` |
| A2 🚧 | 上面修完后仍偶发「几十 MB 要好几秒」 | `tauri.conf.json` 的 CSP 漏了 `connect-src 'self' ipc: http://ipc.localhost` → **永久回退** `webview.eval()` | CSP 必须含这三项。这一条最阴，不报错、只是慢 |
| A3 | 误判两次后才找到 A1 | 先后怀疑 StrictMode 双调用、`createImageBitmap(ImageData)` 原生递归 | 教训：**修 bug 要先验证原因本身**，别顺着第一个像的原因改 |
| A4 🚧 | 图库加目录后窗口「未响应」 | 命令写成同步 `fn`，堵住消息泵 | **重活命令必须 `async fn`**，写文件再加 `spawn_blocking` |
| A5 🚧 | 改 `tauri.conf.json` 不生效（窗口尺寸被钳在旧值） | tauri-build 的 `rerun-if-changed` 不可靠 | 改完 `touch build.rs tauri.conf.json main.rs` 再 `cargo build` |
| A6 🚧 | 迁移到 J: 后构建报 `failed to read plugin permissions ... os error 3` | `target/release/build/tauri-*` 里缓存了**旧绝对路径** | `rm -rf target/release/build/tauri-*` 再全量构建。只删 `photovault-*` 不够 |
| A7 | 往记忆文件里堆细节 → 新会话注入被截尾 | `MEMORY.md` 到 17 KB 就被截断（只注入约 87%） | 分层：`MEMORY.md` 只放结论+禁令，细节进 `MEMORY-dev.md` |

### B 类 · 性能

| # | 现象 | 根因 | 修法 / 现状 |
| --- | --- | --- | --- |
| B1 | 打开一张图慢 **250 倍** | 全图转 RGBA 再缩放 | **降采样在源格式空间做完再转 RGBA**（JPEG 301→218 ms）。⛔ 别先转整幅 RGBA；`fast_image_resize` 的 `rayon` 必须开 |
| B2 🚧 | 大目录首屏 **8–9 秒** | 列目录时对 1224 个文件逐个读魔数判断格式 | `list_dir_images_fast` 走扩展名优先；**只有入库才 `walk_dir` 魔数判定**。降到 **89 ms** |
| B3 🚧 | 列 RAW 目录会整个界面卡死 | 探测尺寸时读了 **47 MB** 去找内嵌预览 | 拦截在 `pv_decode::probe_dimensions`。⛔ 别在 UI 层做尺寸探测 |
| B4 | 缩略图网格滚动卡 | 无并发控制、无懒加载 | 四层防护：后端 async + `thumbQueue`（并发 4）+ `useInView` + `useGridWindow`（预取后 30）。⛔ 预取窗口要能随回滚**变小** |
| B5 | 一页最多显示 500 条 | 查询走了默认 LIMIT | 分页/窗口化查询 |

### C 类 · 数据正确性（最危险）

| # | 现象 | 根因 | 修法 / 现状 |
| --- | --- | --- | --- |
| C1 🚧 | 差点「从图库移除」把**原图删了** | 命令边界没说清 | **移除 = 删索引 + 删缓存，绝不碰原图**；且**先删缓存再删索引行**（缓存键含路径）。护栏 `移除目录只删索引与缓存不碰原图` |
| C2 🚧 | 全盘扫描误入库 **16,628 条** | 「浏览」直接复用了「入库」的命令 | 浏览与入库拆成两套命令，⛔ 永远不许合并 |
| C3 🚧 | 图片被覆盖后仍显示旧图 | 缓存键不含 `mtime` | 原地改写文件后 `ThumbSource.rev` + `bumpThumbs` 强制重取 |
| C4 🚧 | 外部新增/另存为的文件不出现 | 没有重扫机制 | `rescan` 覆盖 browse/folder/library/all + window focus 自动重扫（`all` 不自动、2 秒限流） |
| C5 🚧 | 批量操作对「浏览模式」失效 | 用了 `selectedItems`，而浏览模式该项恒为空 | 文件级批量操作**用右键作用对象或显式 `paths`** |
| C6 🚧 | 删照片顺序错了会留下孤儿 | 先删索引后删文件，中途失败无法回滚 | **先删文件（进回收站）→ 确认不在了 → 才删索引** |
| C7 | 选固定比例后画面乱跳 | 裁剪坐标系按「原图」算，旋转后错位 | `crop` = **「旋转后的图」的归一化坐标**；`frameRect === null` 才等于不裁剪 |
| C8 | 表格里存了盘符，U 盘插拔后全失效 | 直接存 `C:\...` | 存 `volume_guid + rel_path` |
| C9 🚧 | 「信息面板有地点，搜索却搜不到」 | `image_exif` 链路**从不写入**；面板是当场读文件算的 | 地点回填**两段式**：① 有坐标走纯 SQL；② 无行则开文件读 EXIF 并顺带写品牌/机型/镜头，**没 GPS 也落行** |
| C10 | 搜「日落」搜不到「海边日落」 | 想用 FTS5，但 `unicode61` **不切中文** | 走 LIKE + 空格 AND 拆词；`%`/`_` 转字面量（`ESCAPE '\'`） |
| C11 | EXIF 保存报错 | 超过 65533 字节 | **跳过而非报错**。`Orientation` 只在用户旋转过时置 1 |

| # | 现象 | 根因 | 修法 / 现状 |
| --- | --- | --- | --- |
| D1 🚧 | 每张图都被套上白框 + 压暗 | 裁剪框被无条件渲染 | **只在裁剪语境渲染**（`cropUi \|\| aspect!=='free' \|\| frameRect!==null`）。护栏 2 条 |

### E 类 · AI 与算法

| # | 现象 | 根因 | 修法 / 现状 |
| --- | --- | --- | --- |
| E1 🚧 | 聚类把 **221 张脸糊成一簇**（互相不是一个人） | 美颜图让不同人的向量相似度高达 **0.83**，向量全塌向「平均脸」，单阈值必崩 | **两阶段聚类**：`t_core=0.55` 出核心簇 → `t_join=0.50` 按簇心并入。最大簇降到 37 张且全对 |
| E2 🚧 | 小脸向量是纯噪声 | 检测跑在 1024 长边 | **检测必须 2048 长边 + 最小脸 56~80px**。同图负样本 p50 从 0.181 抬到 0.285 |
| E3 🚧 | 阈值怎么调都不对 | 想用「负样本分布上界」机械定阈值（家人长得像 + 美颜图都会让它失真） | 必须导出拼图**人眼核对**：`tools/ai/face_probe.py --dump` |
| E4 | 「工具算的 ≠ 库里存的」 | 把 `+0.02` 类目加成当成了置信度 | 类目加成不参与置信度；分数统一两位小数 |
| E5 | 有人像的照片识别不出人像 | CLIP 零样本判人脸假阳性/假阴性都多 | 人像改由 **YuNet 检测**决定，CLIP 退出这个判断 |
| E6 | 跑脚本漏检大量人脸 | `cv2.imread` **读不了中文路径** | 统一走 `np.fromfile + cv2.imdecode` |
| E7 🚧 | 换模型后整库标签全废 | schema 没记录模型 | `faces.model` 列必须有 —— **换模型要整库重建** |
| E8 | 换 ViT-H/14 精度更高但没用 | 大模型单次推理成本翻倍，收益不可感知 | 两次 A/B 均判「不换」，保持 B/16 |
